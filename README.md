
# Что такое WAL

WAL - Write Ahead Log. В буквально переводе "Журнал упреждающей записи". Он же "бинлог", он же "журнал" (в семантике "журналируемые файловые системы", с оговорками). Это структура данных, способная крайне надёжно сохранить записи в строгой последовательности и по запросу отдать эти записи в той же последовательности обратно. Логически это просто `std::vector<std::string>`.

* Запись - произвольный набор байт;
* Упреждающей - в WAL обычно добавляют запись до "выполнения" этой записи;
* Надёжно сохранить - заведомо надёжнее, чем остальные части системы; причём, WAL может быть просто структурой данных в RAM, а надёжность достигаться за счёт простоты реализации и следующей отсюда низкой вероятности багов; всё же обычно WAL хранят во внешней памяти - блочное устройство, файловая система, другое.
* Отдать обратно - любой запрошенный поддиапазон записей, но в прежнем порядке между ними ("дай записи от 700-й по 750-ю").

WAL - простейший механизм, который только можно придумать, обеспечивающий надёжную фиксацию происходящих изменений сложной системы. WAL - основа любой сложной СУБД или простой key-value хранилки. Можно сказать, что WAL - это план действий, куда система вносит краткие записи о том, что она собирается менять в себе, прежде чем начинать изменения.

# Набор причин, по которым всем всегда нужен WAL

* Структура данных, которую надо менять (таблица в БД, три взаимосвязанных бинарных дерева поиска в памяти и подобное) - сложная, то есть изменения в ней делаются за несколько шагов, а выполнение только половины из них разрушает всю эту струтуру; при этом аварийные остановки в любой точке (убили процесс, умер сервер) никто не отменял;
* Структуру данных изменить разумным способом можно только в ненадёжной памяти, типа RAM, которую могут выключить.

И при всех этих условиях зафиксировать изменение всей глобальной структуры, состоящей из множества компонент, хочется максимально надёжно, атомарно и так просто, чтобы негде было написать багов. Ничего проще, чем линейная последовательность записей в журнале вида "а сейчас я буду делать такое-то изменение" человечество не придумало.

# Самый простой WAL

Открыть файл `open(O_WRONLY | O_APPEND)` и добавлять в его конец записи, а при необходимости проиграть журнал - открыть файл с начала или с нужной точки и прочитать.
