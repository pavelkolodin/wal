
# Что такое WAL

WAL - Write Ahead Log. В буквально переводе "Журнал упреждающей записи". Он же "бинлог", он же "журнал" (в семантике "журналируемые файловые системы", с оговорками). Это структура данных, способная крайне надёжно сохранить записи в строгой последовательности и по запросу отдать эти записи в той же последовательности читателю. Логически это просто `std::vector<std::string>`.

* Запись - произвольный набор байт;
* Упреждающая - записи в WAL обычно добавляют до их "исполнения";
* Надёжно - это заведомо надёжнее, чем остальные части системы; иногда это значит не физическую прочность, а простоту, где негде ошибиться; обычно WAL хранит записи во внешней памяти - блочное устройство, файловая система и т.п.
* Отдать читателю - значит отдать любой запрошенный поддиапазон записей, но гарантированно в том же порядке, в котором записи были добавлены в WAL

WAL - простейший механизм, который только можно придумать, обеспечивающий надёжную фиксацию происходящих изменений сложной системы. WAL - основа любой сложной СУБД или простой key-value хранилки. Можно сказать, что WAL - это план действий, куда система вносит краткие записи о том, что она собирается менять в себе, прежде чем начинать изменения.

# Набор причин, по которым всем всегда нужен WAL

* Изменение структуры данных требует нескольких шагов, но выполнение только части из них разрушает структуру
* Изменить структуру данных можно только в ненадёжной памяти, типа RAM, которую могут выключить
* Нужно максимально надёжно, просто и быстро зафиксировать произошедшее изменение

Зафиксировать изменение сложной структуры проще, чем сформировать запись, описывающую это изменение и положить её в журнал, человечество не придумало.

# Самый простой WAL

## Как записывать

Открыть файл `open(O_WRONLY | O_APPEND)` с именем 0000000000000000 и добавлять в его конец бинарные записи вида

```cpp
struct Record {
  // 1 = set(key, value)
  // 2 = delete(key)    // поле value не используется
  // 3 = increment(key) // поле valuе трактуется как число и добавляется к текущему value в базе.
  uint32_t opcode;
  std::string key;
  std::string value;
};
```

В бинарном (сериализованном) little-endian виде такая структура может выглядеть например так:

```
18 00    aa bb cc dd    01 00 00 00    05 00    07 00    48 45 4c 4c 4f    53 4f 42 41 4b 45 4e
LEN      CRC32C         opcode         klen     vlen     HELLO             SOBAKEN
```

* LEN (2 байта) - длина всей последующей части структуры = (0x18 = 4 + 4 + 2 + 2 + 5 + 7)
* CRC32C (4 байта) - crc32c конкатенации последующих полей
* 4 байта опкод (32-битное число 1 - это set)
* 2 байта длина ключа (16-битное число 5)
* 2 байта длина value (16-битное число 7)
* содержимое key (5 байт "HELLO") (без нулевого байта в конце конечно)
* содержимое value (7 байт "SOBAKEN")

Имя файла является hex числом, обозначающим позицию от глобального начала WAL, на которой находится самая первая запись в этом файле. Когда очередная запись делает размер файла больше некого установленного лимита (64 Мб, например), то эта запись пишется уже в слующий файл. В итоге на диске мы получаем последовательность файлов, размер которых немного недотягивает до 64 мегабайт:

```
0000000000000000  // размер первого файла = 0x3fffd80
0000000003fffd80
0000000007fffd72
000000000bfffc51
000000000ffffbd2
0000000013fffac5
0000000017fff829
```

## Как читать
Открываем файл с начала и пытаемся парсить из него последовательность наших Record.
